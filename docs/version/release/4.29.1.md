## Summary

Owner melaporkan: setelah login, reload dashboard kadang terpental ke `/login` lalu tiba-tiba masuk lagi. Penyebab: middleware `authenticate` menjawab **401** untuk error apa pun di blok `catch` (termasuk MongoDB lambat/putus sesaat). Saat reload, dashboard menembak banyak API sekaligus; satu 401 palsu membuat `queryClient` melakukan hard redirect ke `/login`, lalu halaman login melihat sesi masih valid (`/api/auth/me` sukses) dan mengembalikan ke `/dashboard`. Selain itu `AuthProvider` menganggap timeout/5xx/429 pada `/api/auth/me` sebagai "belum login". Rilis ini membedakan token tidak valid (401) dari gangguan sementara (503) dan membuat cek sesi di client mencoba ulang.

## Highlights

- `authenticate`: 401 hanya untuk JWT invalid/kedaluwarsa; error lain → 503 `AUTH_TEMPORARILY_UNAVAILABLE`.
- `AuthProvider` & `TenantAuthProvider`: cek sesi retry (0 / 0,8 / 2 / 4 dtk) untuk timeout, jaringan, 429, 5xx; hanya 401/403 = logout.

## Features (detail)

### Change A — Bedakan 401 vs gangguan sementara
- **Masalah / tujuan:** logout palsu saat DB lambat.
- **Perilaku baru:** `JsonWebTokenError`/`TokenExpiredError`/`NotBeforeError` → 401; lainnya → 503 (tercatat di log server). `queryClient` sudah memperlakukan 503 sebagai transient (retry), bukan redirect.
- **Siapa terdampak:** semua pengguna login (main & komunitas).
- **Permission:** —
- **Tenant-aware:** Yes
- **Source:** `server/auth.ts`, `client/src/lib/auth.tsx`, `client/src/lib/tenant-auth.tsx`
