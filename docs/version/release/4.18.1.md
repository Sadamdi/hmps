## Summary

Setelah Overview Suite Phase 2 (SSE system-health), ring CPU di dashboard sering stuck di ~93–100% dengan label “1 cores”, sementara `uptime`/load average host tetap rendah (~0.0–0.7) dan proses top hanya menunjukkan `hmps-app` ~4% serta `clamd` ~0–1%. Root cause: `getCpuUsage()` mengambil delta `os.cpus()` dalam window **100ms** — pada host **1 vCPU**, burst singkat (SSE tick, GC, I/O) membuat sample terlihat penuh. Patch ini memakai background sampler 1 detik + EMA, dan memperbaiki pluralisasi label core.

Verifikasi ops terpisah: ClamAV daemon aktif, `clamdscan` mendeteksi EICAR, dan app log `ClamAV scanner initialized successfully` — scan-on-upload tetap hidup (koleksi `fileuploads` kosong hanya karena belum ada upload baru).

## Highlights

- CPU gauge Overview mengikuti load aktual, bukan spike 100ms
- Label core singular/plural benar
- Tidak mengubah kontrak API system-health / SSE

## Features (detail)

### Change — Accurate CPU usage sampling
- **Masalah / tujuan:** Widget System Health menampilkan CPU hampir selalu 100% pada production 1-vCPU padahal load average rendah.
- **Perilaku baru:** `ensureCpuSampler()` jalan tiap 1s di background; nilai ditampilkan dihaluskan EMA (α=0.35); seed awal dari `loadavg[0]/cores` agar tick pertama tidak 0 palsu.
- **Siapa terdampak:** admin / role dengan `overview.system_health`
- **Permission:** tidak berubah (`overview.system_health`)
- **Tenant-aware:** No (host metrics)
- **Source:** `server/lib/system-health.ts`

### Change — Core label grammar
- **Masalah / tujuan:** Teks `1 cores` di CardDescription
- **Perilaku baru:** `1 core` / `N cores`
- **Siapa terdampak:** dashboard Overview
- **Source:** `client/src/pages/dashboard/widgets/system-health.tsx`
