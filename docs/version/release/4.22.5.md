## Summary

First visit to the homepage sometimes showed empty berita, events, organization, or hero photos until a full reload. Root causes: Nginx API `limit_conn 12` + `10r/s` rejecting part of the ~15–22 parallel GETs, plus React Query `retry: false` and empty placeholders treating failures as “no data”. Fix: transient retries, error+retry UI on home sections, dedupe home-images/store-settings fetches, raise Nginx API limits and isolate SSE connections, expand DDoS concurrent skip list for public GETs.

## Highlights

- React Query retries 429/502/503/504 (2x backoff)
- Home sections show “Coba lagi” instead of fake empty state
- Nginx API limit_conn 12→32, rate 10→20r/s; SSE separate zone
- Dedup `/api/home-images/active` via QueryClient in app loader

## Fixed

- Intermittent empty home content on cold load
- Hero intro blocked forever when `home-images` fetch failed (`dataReady`)

## Security

- API Origin/auth protection unchanged; only concurrent-slot skip expanded for public GETs
- Nginx still rate-limits; thresholds raised for legitimate SPA burst

## Ops / Tooling

- After deploy: copy/reload `nginx-himatif-encoder.conf` on server (`nginx -t && systemctl reload nginx`) — app auto-deploy alone does not apply nginx changes
