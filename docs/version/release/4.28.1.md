## Summary

Verifikasi 4.28.0 di produksi: lookup ID sudah dilewati, halaman pertama masuk (47 item, pinned benar, avatar & ID tersimpan), tetapi Instagram membatasi di halaman ke-2. Karena setiap percobaan mulai lagi dari halaman 1, arsip ±1.208 post tidak akan pernah lengkap. Rilis ini menyimpan cursor `next_max_id` dan melanjutkan backfill tiap jam (maks 3 halaman per run) sampai selesai.

## Highlights

- Cursor backfill IG tersimpan (`cache.backfillCursor.instagram`).
- Cron per jam (menit 17) melanjutkan backfill situs utama, maks 3 halaman.
- Pin dipertahankan saat melanjutkan; item terhapus hanya dibersihkan pada run penuh satu kali jalan.

## Features (detail)

### Change A — Cursor & lanjutan per jam
- **Masalah / tujuan:** backfill selalu terhenti di halaman 2.
- **Perilaku baru:** `ig_feed.py` menerima `IG_START_MAX_ID`/`IG_MAX_PAGES`, mengembalikan `nextMaxId`; sync menyimpan/menghapus cursor; cron `17 * * * *` menjalankan sync IG `full` hanya bila cursor ada.
- **Siapa terdampak:** public (arsip IG bertambah bertahap), ops.
- **Permission:** —
- **Tenant-aware:** No (lanjutan per jam hanya situs utama; tenant tetap lewat cron harian)
- **Source:** `ops/instagram/ig_feed.py`, `server/services/instagram-instagrapi.ts`, `server/services/social-feed.ts`, `shared/social-feed.ts`, `server/index.ts`
