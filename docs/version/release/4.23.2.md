## Summary

Dua patch lanjutan dari v4.23.1:

1. **Pipeline decode HEIC/HEIF di server masih gagal walaupun v4.23.1 sudah terima mimetype & ekstensi.**
   - Penyebab: `sharp@0.34.x` prebuilt binaries **tidak include HEVC decoder** (`libde265`). Sharp hanya support AVIF (AV1) out-of-the-box; HEIC (HEVC in HEIF container) butuh libvips yang di-compile manual dengan `--enable-libheif`.
   - Solusi: tambah dependency `heic-convert@^2.1.0` (pure-JS, N-API bindings ke `libheif`). Cross-platform tanpa butuh system `libheif`/`libde265`. `processImage()` sekarang: deteksi HEIC via ISOBMFF `ftyp` box → decode ke JPEG via `heic-convert` → pipeline sharp (rotate/resize/webp) seperti biasa.
2. **Section header Berita/About/Visi&Misi masih bisa invisible.**
   - Patch v4.23.1 menambah viewport check + fallback timeout 800 ms (hanya reveal kalau dalam viewport). Di skenario tertentu (user scroll cepat / tab inactive / section masih di luar viewport pada mount), observer tidak fire DAN viewport check di fallback return `false` karena section belum masuk viewport → state stuck `false`.
   - Solusi: fallback timeout sekarang **memaksa `isVisible = true` tanpa peduli posisi viewport**, ditambah fallback kedua di 2500 ms sebagai safety net. Rationale: section header yang "hilang" adalah bug UX fatal; reveal sedikit lebih awal hanya masalah kosmetik.

## Highlights

- Upload `.heic`/`.heif` benar-benar jalan end-to-end sekarang: dari iPhone Safari → server backend → output WebP di `/uploads/...`.

## Features (detail)

### Feature A — HEIC/HEIF pipeline decode via `heic-convert`

- **Masalah / tujuan:** Setelah v4.23.1, validasi mimetype/ekstensi sudah benar, tapi file HEIC yang lolos validasi tetap gagal diproses di server karena `sharp` tidak bisa decode HEVC codec. Sebelumnya hanya AVIF (AV1) yang bisa lewat.
- **Pendekatan:**
  - Tambah package `heic-convert@^2.1.0` (pure-JS decoder, N-API bindings `libheif`).
  - Tambah `looksLikeHeic(buffer)` di `server/image-processor.ts` — deteksi via ISOBMFF `ftyp` box header (4 bytes pertama setelah size = `ftyp`, lalu major brand salah satu dari `heic/heix/hevc/hevx/heim/heis/heics/heicm/mif1/msf1`).
  - Tambah `decodeHeicToJpeg(input)` — `heic-convert` decode HEIC → JPEG intermediate (quality 92).
  - `processImage()` pipeline: kalau `looksLikeHeic(inputBuffer)` → decode ke JPEG dulu → masuk pipeline sharp `rotate → resize → webp` seperti biasa.
- **Siapa terdampak:** semua user yang upload gambar dari iPhone (HEIC) atau kamera HEIF.
- **Permission:** sama seperti upload existing (auth + permission sesuai endpoint).
- **Tenant-aware:** Yes — `processImage()` dipanggil dari `server/upload.ts` di jalur main + tenant, semua jalur mendapat perlakuan yang sama.
- **Source:**
  - `server/image-processor.ts` (tambah `looksLikeHeic`, `decodeHeicToJpeg`, modifikasi `processImage`)
  - `package.json` (tambah dependency `heic-convert@^2.1.0`)
  - `types/heic-convert.d.ts` (BARU — type declarations lokal karena package tidak punya `@types/...` resmi)
  - `tsconfig.json` (tambah `types/**/*` ke `include`)

### Feature B — Section header reveal hardening

- **Masalah / tujuan:** v4.23.1 menambah fallback timeout 800 ms tapi hanya reveal kalau section sudah dalam viewport. Di skenario tertentu (section masih jauh di bawah viewport pada mount), observer tidak fire dan fallback reveal tidak terjadi karena viewport check return `false`. State `isVisible` stuck `false` → header invisible.
- **Pendilaku baru:**
  - Fallback timeout 800 ms sekarang: `setIsVisible(prev => prev || true)` — paksa reveal tanpa peduli viewport.
  - Fallback tambahan 2500 ms sebagai safety net terakhir.
  - Rationale: section header yang hilang adalah bug UX fatal (user tidak bisa navigate section); reveal sedikit lebih awal dari yang ideal hanya masalah kosmetik (animasi reveal mungkin tidak ke-trigger kalau user sudah scroll lewat).
- **Siapa terdampak:** semua section yang pakai `useRevealAnimation` (`berita`, `about`, `vision-mission`, `library`).
- **Permission:** N/A (FE only).
- **Tenant-aware:** N/A (FE only).
- **Source:** `client/src/hooks/use-reveal-animation.ts`

## Fixed

- **Bug:** Upload HEIC/HEIF masih gagal di server setelah v4.23.1. **Gejala:** upload sukses sampai validasi mimetype/ekstensi, lalu `Error: Input buffer contains unsupported image format` dari sharp. **Root cause:** sharp prebuilt binaries tidak include HEVC decoder; HEIC butuh libheif yang harus di-compile manual. **Fix:** gunakan `heic-convert` (pure-JS) untuk decode HEIC → JPEG intermediate, lalu pipeline sharp biasa.
- **Bug:** Section header Berita/About/Visi&Misi/Library masih bisa stuck invisible. **Gejala:** section tampil tanpa pill/judul/garis/deskripsi. **Root cause:** fallback timeout v4.23.1 hanya reveal kalau section dalam viewport; kalau section masih jauh di bawah, observer tidak fire dan fallback return `false`. **Fix:** fallback timeout hard reveal tanpa syarat viewport, plus fallback tambahan 2500 ms.

## Notes / Known gaps

- `heic-convert` adalah pure-JS decoder yang relatif lebih lambat dari libvips native (`~50-200ms` per HEIC foto vs `<10ms` di native). Untuk foto iPhone ukuran 12MP, decoding ke JPEG intermediate sekitar 100-300ms — masih dalam batas acceptable untuk upload.
- Image preview di FE sebelum upload (HTML `<img src=objectURL>`) mungkin blank di Firefox/Chrome untuk HEIC (browser tidak punya HEVC codec). Setelah upload selesai, URL yang tersimpan adalah `.webp` yang universal — gambar tampil di list setelah refresh.
- AVIF pipeline tetap via sharp langsung (sudah didukung libvips prebuilt untuk AV1 codec).
- Future improvement: cache hasil decode HEIC per-buffer hash untuk menghindari decode ulang kalau user upload file yang sama dua kali. (Di luar scope patch.)
