## Summary

Deploy 4.28.2 (27 Sep 12:54) membuat server tidak merespons ±4 menit (HTTP 502 + SSH timeout). Skrip deploy sudah menghentikan `hmps-app` dan `himatif-banner` sebelum build, tetapi RAM tersisa hanya ±700MB karena `clamd` (ClamAV) memakan ±1GB; kernel lalu meng-OOM-kill `clamd` di tengah build (juga terjadi 25 Sep). Swap tidak bisa dipakai: server adalah container OpenVZ (`swapon: Operation not permitted`, `/swapfile` 2GB sudah ada sejak 12 Agustus). Rilis ini menghentikan `clamav-daemon` selama install/build dan menyalakannya kembali — menunggu socket siap — sebelum app di-restart.

## Highlights

- `clamav-daemon` ikut di-stop saat build (`HMPS_STOP_SERVICES`).
- `clamd` dinyalakan lagi & ditunggu siap (maks 180s) sebelum restart app, juga saat build gagal.
- `ssh`, `cloudflared`, `nginx`, `pm2-root`, `hmps-auto-deploy`, akses remote tidak disentuh.
- `ensure-swap.sh` dipanggil walau tanpa bit eksekusi (hanya warning di OpenVZ).

## Features (detail)

### Change A — Stop service berat selama build
- **Masalah / tujuan:** OOM saat vite build di VPS 2GB tanpa swap.
- **Perilaku baru:** `stop_heavy_services` setelah `pm2_stop_apps`; `start_heavy_services` di awal `pm2_start_apps` dan di trap cleanup (selalu, termasuk gagal build). Urutan clamd → tunggu socket `/var/run/clamav/clamd.ctl` → app, karena `server/services/file-scanner.ts` meng-cache status ClamAV saat init.
- **Siapa terdampak:** ops.
- **Permission:** —
- **Tenant-aware:** No
- **Source:** `ops/deploy-server.sh`

## User-facing impact

- Downtime build tetap ±3–4 menit (app memang di-stop), + ≤ waktu start clamd; risiko server hang/OOM berkurang.
