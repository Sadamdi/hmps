## Summary

Dashboard Feedback (/dashboard/feedback) tab **Daftar Bug** dan **Bug Otomatis** sebelumnya memuat seluruh item sekaligus tanpa filter tanggal, pencarian teks, atau pagination. Seiring waktu produksi, jumlah dokumen `BugReport` dan `SystemError` membengkak sehingga loading list lambat dan beban server tinggi. Rilis ini membatasi 10 item per halaman dengan pagination, menambahkan filter rentang tanggal (dari–sampai), pencarian teks, filter severity (khusus SystemError), filter tenant (web utama vs komunitas), dan toggle sort. Perubahan dilakukan di backend (query contract `GET /api/feedback/bug-report/list` dan `GET /api/system-errors/list`) dan frontend (komponen reusable `BugFilterBar` + state + Pagination). Tidak ada perubahan business logic.

## Highlights

- Daftar Bug & Bug Otomatis kini **pagination 10 item per halaman** (mengurangi payload + beban render)
- Filter rentang tanggal `dateFrom`–`dateTo` (ISO `YYYY-MM-DD`, UTC) di kedua tab
- Pencarian teks `q` (regex escaped) untuk deskripsi/nama/email/username (Bugs) atau name/message/route/file (SystemError)
- Filter severity **Low/Medium/High/Critical** dan tenant **Web Utama / Tenant / Semua** di tab Bug Otomatis
- Toggle sort **Terbaru dulu** (default) / **Terlama dulu** di kedua tab
- Komponen reusable `BugFilterBar` siap dipakai surface lain di FE
- Empty state updated: membedakan "belum ada data" vs "filter tidak menghasilkan apa-apa"

## Features (detail)

### Feature A — Pagination + filter untuk `GET /api/feedback/bug-report/list`

- **Masalah / tujuan:** Tanpa pagination, daftar Bug Report yang dikirim user dari main + tenant berpotensi mengirim ratusan dokumen ke FE pada satu kali render. Belum ada filter tanggal / pencarian sama sekali, menyulitkan investigasi.
- **Perilaku baru:** Endpoint menerima `page`, `limit` (default 10, cap 100), `status`, `dateFrom`, `dateTo`, `q`, `sort`. Pencarian regex di-escape untuk mencegah ReDoS/injection. Rentang tanggal memakai ISO `YYYY-MM-DD` dengan asumsi UTC (start-of-day & end-of-day).
- **Siapa terdampak:** owner (hanya owner yang boleh akses endpoint)
- **Permission:** `role === 'owner'`
- **Tenant-aware:** No (data sudah lintas-tenant via `sourceCommunitySlug`)
- **Source:** `server/routes/feedback.ts`

### Feature B — Pagination + filter untuk `GET /api/system-errors/list`

- **Masalah / tujuan:** Sama dengan di atas — koleksi `SystemError` lintas-tenant membengkak. Plus kebutuhan filter cepat berdasarkan severity dan tenant origin (mis. "lihat hanya error critical dari tenant X").
- **Perilaku baru:** Query param `isTenant` (`true`/`false`), `communitySlug` (exact), `severity`, `status`, `source`, `dateFrom`, `dateTo`, `q`, `sort`, `page`, `limit` (default 10). Pencarian regex aman, rentang tanggal UTC.
- **Siapa terdampak:** owner
- **Permission:** `role === 'owner'`
- **Tenant-aware:** Conditional — filter tenant memudahkan inspeksi lintas-tenant
- **Source:** `server/routes/system-errors.ts`

### Feature C — `BugFilterBar` reusable component (FE)

- **Masalah / tujuan:** Tidak ada UI konsisten untuk filter rich di kedua tab. Pakai inline form akan duplikasi.
- **Perilaku baru:** Komponen `<BugFilterBar />` dengan props `value` (state), `onApply`, `onReset`, `loading`, `queryPlaceholder`. Render: search + sort select di row 1; date range + tombol Terapkan & Reset di row 2. Local state di-sinkronkan dengan prop `value` via `useEffect` agar parent controlled.
- **Siapa terdampak:** developer FE (reusable untuk surface filter rich lain di kemudian hari)
- **Permission:** N/A
- **Tenant-aware:** N/A
- **Source:** `client/src/components/dashboard/bug-filter-bar.tsx` (BARU)

### Feature D — Pagination UI di feedback.tsx

- **Masalah / tujuan:** Tab Bugs/SystemBugs belum punya pagination.
- **Perilaku baru:** Pakai komponen `<Pagination />` existing (dengan `currentPage`, `totalPages`, `onPageChange`). Wrapper info "Halaman N dari M · Total X". Hanya render bila `total > pageSize`. State `bugPage`/`sysPage` di-reset ke 1 setiap filter/sort berubah.
- **Siapa terdampak:** owner
- **Permission:** `role === 'owner'`
- **Tenant-aware:** No
- **Source:** `client/src/pages/dashboard/feedback.tsx`

## User-facing impact

- Halaman/route: `/dashboard/feedback` → tab **Daftar Bug** & **Bug Otomatis**
- UX: ada filter bar (search + sort + date range + Terapkan/Reset) di bawah tombol filter status/sumber. Pagination di bawah list. Empty state baru menjelaskan apakah list kosong atau filter terlalu sempit.
- Smoke test: login owner → buka `/dashboard/feedback` → tab Bugs → pilih "Open" → isi date range → klik Terapkan → cek list max 10 + pagination. Tab Bug Otomatis → pilih "Critical" + source Server → cek list max 10 + pagination. Reset filter → page kembali 1.

## Security

- Input validation: `dateFrom`/`dateTo` divalidasi dengan regex `^\d{4}-\d{2}-\d{2}$` sebelum dipakai `new Date()`; format invalid diabaikan agar tidak crash query
- `q` di-escape dengan pola `[.*+?^${}()|[\]\\]` → `\\$&` untuk mencegah regex injection / ReDoS
- `q` di-cap 100 char untuk mencegah query regex panjang
- Owner-guard tetap enforce (tidak bocor ke non-owner)
