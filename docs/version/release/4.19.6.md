## Summary

Setelah `4.19.5` di-deploy, pengecekan cepat sempat menunjukkan iframe masih macet — memicu commit debug (`b83ee5a`, tidak versioned, murni instrumentasi) yang menambahkan `console.log` di titik-titik kunci (`effect run`, `observer attached`, `observer callback`) untuk melihat apa yang sebenarnya terjadi di runtime production.

Log runtime yang ditangkap membuktikan mekanisme `4.19.5` **bekerja dengan benar**: `IntersectionObserver` berhasil attach ke elemen yang tepat, callback-nya fire dengan `isIntersecting: true` begitu elemen masuk viewport (dibuktikan lewat `entry.boundingClientRect`), state `driveIframeInView` berhasil di-set `true`, dan komponen re-render menampilkan iframe. Pengujian ulang dengan scroll bertahap + jeda yang cukup (bukan cek instan) menghasilkan **7/7 iframe berhasil muat, 0 spinner tersisa, 7/7 tombol fallback "Buka di Drive" tampil** — konsisten di beberapa kali percobaan reload.

Kesimpulan: kegagalan yang terlihat sebelumnya adalah artefak metodologi pengujian (skrip verifikasi mengecek DOM sebelum React sempat commit re-render + iframe sempat memuat kontennya), bukan bug nyata di kode `4.19.5`. Rilis ini murni membersihkan instrumentasi debug yang sempat ditambahkan.
