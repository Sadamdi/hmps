## Summary

Hasil pentest read-only terhadap build produksi menemukan beberapa kelemahan pada
lapisan kepercayaan: gerbang chat yang hanya membaca header kiriman klien, proxy
pratinjau dokumen tanpa daftar host (SSRF), proxy Google Drive yang memakai service
account tanpa pembatasan, pengungkapan keberadaan akun pada alur lupa password, dan
aturan hierarki role yang tidak konsisten di backend. Versi ini menutup semuanya
tanpa mengubah alur kerja harian pengurus maupun tampilan publik.

Prinsip yang dipakai: **jangan percaya apa pun yang ditulis klien**. Semua keputusan
otorisasi tetap di server, dan setiap nilai yang dipakai ulang (nama role, fileId,
URL pratinjau, cookie sesi) divalidasi ulang sebelum dipakai.

## Highlights

- Role `owner` tidak bisa diturunkan/diubah siapa pun, termasuk oleh pemiliknya sendiri — ditegakkan di backend, bukan hanya UI
- Hierarki role kini dicek dua arah; satu endpoint yang sebelumnya tanpa cek sama sekali sudah diperbaiki
- `/api/prodi/preview` memakai allowlist host + validasi tiap redirect (SSRF tertutup)
- Proxy Google Drive hanya melayani file yang benar-benar dipakai konten publik
- Chat punya sesi bertanda tangan HMAC + anggaran harian LLM, agar biaya API tidak bisa dibebankan orang luar
- Lupa password tidak lagi membocorkan email mana yang terdaftar

## Features (detail)

### Change A — Role owner terkunci di backend
- **Masalah / tujuan:** role paling atas bisa diturunkan oleh siapa pun yang punya akses dashboard, termasuk oleh owner sendiri. Salah satu handler (`authorize(['owner','admin',...])`) tidak memeriksa hierarki sama sekali.
- **Perilaku baru:** `PUT /api/users/:id/role` (dua jalur) dan `PUT /api/roles/:id` menolak perubahan yang menyentuh role level tertinggi. Hierarki dicek dua arah: target harus lebih rendah, dan role yang diberikan harus lebih rendah.
- **Siapa terdampak:** admin / owner / dashboard
- **Permission:** `roles.assign`, `roles.edit`, `roles.create` (tidak berubah)
- **Tenant-aware:** Ya (peta level dibaca lewat `resolveStorage(req)`)
- **Source:** `server/auth.ts`, `server/routes.ts`

### Change B — SSRF tertutup pada pratinjau dokumen
- **Masalah / tujuan:** `/api/prodi/preview?url=` memanggil `fetch()` atas URL apa pun dengan `redirect:'follow'`. Terbukti bisa menjangkau `http://127.0.0.1:5000`.
- **Perilaku baru:** hanya host di allowlist, hanya http/https, IP literal dan hostname tanpa titik ditolak, redirect divalidasi per hop (maks 3) dengan `redirect:'manual'`.
- **Siapa terdampak:** public (halaman `/prodi`)
- **Permission:** tidak ada (publik)
- **Tenant-aware:** Tidak
- **Source:** `server/lib/server-fetch-guard.ts`, `server/routes.ts`

### Change C — Proxy Google Drive dibatasi
- **Masalah / tujuan:** `/api/gdrive/stream/:fileId` dan `/api/gdrive/media-url` memakai service account tanpa memeriksa apakah fileId memang dipakai konten publik.
- **Perilaku baru:** fileId harus dirujuk berita/event published atau koleksi library. `media-url` memakai `authenticateOptional`; staf yang login tetap bebas untuk kebutuhan dashboard. `folder-contents` memvalidasi bentuk folderId.
- **Siapa terdampak:** public (video/dokumen di berita, event, galeri)
- **Permission:** publik untuk file yang dipakai konten; staf bebas setelah login
- **Tenant-aware:** Ya (model dari `resolveModels(req)`)
- **Source:** `server/event-attachments.ts`, `server/routes.ts`

### Change D — Chat: sesi bertanda tangan + anggaran LLM
- **Masalah / tujuan:** gerbang `requireTrustedChatOrigin` dan safety-net `api-protection` hanya membaca `Origin`/`Sec-Fetch-Site`. Tiga header palsu cukup untuk memanggil model berbayar.
- **Perilaku baru:** cookie `userId` menjadi `<uuid>.<hmac-sha256>`; `POST /message` wajib sesi tamu bertanda tangan atau sesi staf. Budget harian per IP (default 40) dan global (default 2000) membalas 429 saat habis.
- **Siapa terdampak:** public (widget chat Enco)
- **Permission:** izin tool tetap dari sesi staf server-side (tidak berubah)
- **Tenant-aware:** Ya (cookie di-scope per host; scope chat mengikuti tenant)
- **Source:** `server/routes/chat.ts`, `server/middleware/llm-budget.ts`

### Change E — Anti-enumerasi email pada lupa password
- **Masalah / tujuan:** email tidak terdaftar dibalas 404, email terdaftar dibalas 200 — penyerang bisa memetakan akun.
- **Perilaku baru:** semua hasil dibalas 200 dengan pesan generik. `challengeId` hanya diterbitkan bila akun benar-benar ada. Rate limit per email juga tidak membedakan respons. Frontend menampilkan notice netral dan tetap di langkah email.
- **Siapa terdampak:** public (halaman `/login` → lupa password)
- **Permission:** tidak ada
- **Tenant-aware:** Ya (lewat `resolveModels(req)`)
- **Source:** `server/routes.ts`, `client/src/components/auth/forgot-password.tsx`

### Change F — OTP: pepper pada hash
- **Masalah / tujuan:** `sha256(6 digit)` tanpa pepper bisa diprecompute bila dump database bocor.
- **Perilaku baru:** `HMAC-SHA256` dengan `OTP_PEPPER` (fallback turunan `GUEST_KEY_PEPPER`); generator memakai `crypto.randomInt` sehingga digit terdistribusi rata.
- **Siapa terdampak:** auth (lupa password, ganti email, ganti password, backup restore)
- **Permission:** tidak ada
- **Tenant-aware:** Tidak
- **Source:** `server/services/otp.ts`

### Change G — Allowlist `api-protection` jadi eksplisit
- **Masalah / tujuan:** `path.startsWith(route)` membuat sub-route baru di bawah prefix lama otomatis mewarisi bypass.
- **Perilaku baru:** aturan `exact` / `prefix` / `pattern`. Rute publik yang dipanggil SPA saat first load didaftarkan eksplisit.
- **Siapa terdampak:** seluruh API
- **Permission:** tidak berubah (otorisasi tetap di route masing-masing)
- **Tenant-aware:** Ya (`/api/c` prefix)
- **Source:** `server/middleware/api-protection.ts`

## Security

| Temuan | Sebelum | Sesudah |
|---|---|---|
| SSRF `/api/prodi/preview` | 200 ke `127.0.0.1:5000` | 400, host ditolak |
| Chat gate bypass via header palsu | 200 tanpa cookie | 403 `CHAT_SESSION_REQUIRED` |
| Biaya LLM tanpa batas | tidak ada cap | 429 setelah kuota harian |
| Drive service account | fileId apa pun | hanya file yang dipakai konten publik |
| Enumerasi email | 404 vs 200 | 200 identik |
| Owner diturunkan | mungkin, dua jalur | 403 di semua jalur |
| Hash OTP | sha256 polos | HMAC + pepper |

Env opsional baru (semua punya default aman, tidak wajib):
`SERVER_FETCH_ALLOWED_HOSTS`, `CHAT_SESSION_SECRET`, `OTP_PEPPER`,
`LLM_DAILY_PER_IP`, `LLM_DAILY_GLOBAL`.

## Migration

Tidak ada migrasi data. Catatan operasional:

1. OTP yang sedang berjalan saat deploy menjadi tidak valid (TTL 10 menit).
2. Cookie `userId` chat lama (UUID polos) tidak lagi sah untuk mengirim pesan; pengunjung mendapat cookie baru otomatis saat membuka halaman chat.
3. `PUT /api/users/:id/role` kini menolak perubahan pada user ber-role `owner`. Bila ada kebutuhan darurat mengganti owner, harus lewat langkah ops manual di database dengan persetujuan eksplisit.
