## Summary

Setelah 4.15.1 live, retest Chrome isolasi tenant menemukan dua sisa: breadcrumb Login memakai `basePath` di dalam `Router base=/:slug` sehingga Beranda menuju `/:slug/:slug`; `HeroPersonContent` / banner / slideshow masih `|| DEFAULT_IMAGE_URL` (logo Himatif) jika tenant belum upload banner. Unit ini menutup keduanya. Web utama tidak berubah: login `/` tetap beranda Himatif, hero kosong tetap logo default.

## Highlights

- Breadcrumb Login tenant: `href="/"` (base wouter) — tidak double-slug
- Hero tenant tanpa banner: fallback `logoUrl` atau kosong, bukan logo Himatif
- Hero main tanpa banner: tetap `DEFAULT_IMAGE_URL`

## Features (detail)

### Feature / Change A — Login breadcrumb

- **Masalah / tujuan:** `homeHref = basePath` + wouter `Link` di dalam `Router base` → `/ontakiuinmalang/ontakiuinmalang`.
- **Perilaku baru:** `homeHref = '/'`. Main Login breadcrumb tetap `/`.
- **Siapa terdampak:** public / tenant login
- **Permission:** public
- **Tenant-aware:** Yes
- **Source:** `client/src/components/auth/login-form.tsx`

### Feature / Change B — Hero fallback isolasi

- **Masalah / tujuan:** `HeroPersonContent` / banner / mobile slideshow memakai `DEFAULT_IMAGE_URL` jika src kosong. UINUX menampilkan logo Himatif di slot “Orang”.
- **Perilaku baru:** `fallbackSrc` dari `hero.tsx`: tenant = `logoUrl` atau kosong; main = `DEFAULT_IMAGE_URL`. Renderer tidak memaksa Himatif jika fallback kosong.
- **Siapa terdampak:** public / tenant
- **Permission:** public
- **Tenant-aware:** Yes
- **Source:** `client/src/components/public/hero.tsx`, `client/src/components/public/hero-renderer.tsx`
