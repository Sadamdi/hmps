## Summary

Pengurus yang sudah login masih diminta login lagi saat berbelanja, dan pembeli tidak punya jalan ke dashboard. Sekarang keduanya satu identitas: bisa pindah peran tanpa login ulang, dengan backend dan cookie tetap terpisah.

## Added

- `POST /api/buyer/from-staff`: pengurus yang login membuka akun pembeli dengan email pengurusnya (dibuat otomatis, hash password disalin, tanpa OTP).
- `POST /api/auth/switch-to-staff`: pembeli dengan email terverifikasi yang juga pengurus masuk dashboard tanpa login ulang; limiter sendiri.
- `/api/buyer/me` memberi `alsoStaff`.
- Menu akun pembeli di navbar (akun saya, masuk sebagai pengurus, keluar); item "Akun pembeli" di menu pengurus.
- Kartu "Belanja sebagai pembeli" di checkout dan banner di halaman masuk toko untuk pengurus yang sudah login.
- Halaman login pengurus: tautan "Daftar sebagai pembeli", teks footer satu pintu.
- Password pembeli ikut password pengurus (`Customer.staffLinked`): ganti/reset password pengurus menyinkronkan akun pembeli yang tertaut.

## Fixed

- Nama di navbar terpotong pada huruf "s" (regex `[s@]` seharusnya `[\s@]`); kode lama dihapus bersama tautan tunggal.

## Security

- Pembeli → pengurus hanya untuk email pembeli yang terverifikasi (OTP/Google) dan memakai logika pencocokan yang sama dengan login Google pengurus (tingkat bukti setara "lupa password" lewat email). Pengurus tidak bisa dibuat dari sisi pembeli.
- Pengurus → pembeli tidak mengklaim pesanan lewat email (email pengurus tidak diverifikasi oleh pembeli); hanya lewat perangkat.
- Sinkron password satu arah (pengurus → pembeli) dan hanya untuk akun `staffLinked`; sesi pembeli lama dicabut.

## Verification

- `npm run check` lolos.
- E2E pindah peran **18/18** (pengurus→pembeli, dua sesi bersamaan, password sama, pembeli→pengurus, pembeli biasa ditolak 403, tanpa sesi 401).
- Browser: navbar pengurus menampilkan "Akun pembeli", navbar pembeli menampilkan "Masuk sebagai pengurus", klik berpindah ke /dashboard.

## Notes / Known gaps

- Sinkron password saat pengurus mengganti password belum diuji end-to-end (alur OTP), hanya fungsi dan jalur pembuatan awal.
- Perubahan password dari sisi pembeli tidak mengubah password pengurus (sengaja, satu arah).
- Email pengurus ada di beberapa konteks → pembeli diarahkan ke /login untuk memilih.
