## Summary

Sejak v4.25.0 daftar post Instagram hampir selalu diblokir (jalur web `web_profile_info` 429/302, bahkan dengan cookie login). Rilis ini menambahkan sumber utama baru: skrip Python `ops/instagram/ig_feed.py` berbasis instagrapi (API mobile) yang login dengan sesi akun dummy dan mengembalikan post/reel lengkap (caption, thumbnail, tanggal, carousel). Sesi dibootstrap dari export cookie browser dan state-nya ditulis ulang setiap sync sehingga cookie yang dirotasi Instagram otomatis tersimpan; bila sesi mati, sistem login ulang dengan kredensial akun dummy. Risiko utama: instagrapi memakai API privat Instagram (di luar ToS) — akun dummy bisa kena checkpoint; jalur lama tetap menjadi fallback.

## Highlights

- Instagram: sumber utama instagrapi (diuji lokal: 44 item post/reel terambil).
- Auto refresh cookie: state instagrapi + file cookie browser diperbarui otomatis.
- Login ulang otomatis bila sesi mati (tanpa bypass checkpoint/2FA).
- Status sesi aman (tanpa nilai cookie) di `GET /api/social-feed/manage`.
- File sesi & state di-gitignore; dikirim ke server lewat `scp`, bukan git.

## Features (detail)

### Feature / Change A — Bridge instagrapi
- **Masalah / tujuan:** jalur web Instagram menolak daftar post; butuh sumber yang stabil.
- **Perilaku baru:** `syncInstagramFeed` memanggil `python3 ops/instagram/ig_feed.py <username> <limit>` lebih dulu; item dari instagrapi tidak perlu enrich embed. Bila gagal, rantai lama (web_profile_info → HTML → manual → cache) berjalan seperti biasa.
- **Siapa terdampak:** public (feed beranda & `/media/instagram`), admin (dashboard).
- **Permission:** tidak berubah.
- **Tenant-aware:** Conditional — sesi akun dummy global per server; username tetap dari config tiap tenant.
- **Source:** `ops/instagram/ig_feed.py`, `server/services/instagram-instagrapi.ts`, `server/services/social-feed.ts`

### Feature / Change B — Sesi akun dummy & auto refresh
- **Masalah / tujuan:** cookie IG kedaluwarsa/dirotasi; harus terus berlaku tanpa campur tangan.
- **Perilaku baru:** `server/services/instagram-session.ts` membaca `.instagram-session.json` (export cookie browser) atau env, menyerap `set-cookie` dan menyimpannya, menandai sesi invalid pada 401/403/login_required (file jadi `.expired`), login ulang dengan cooldown 6 jam. Python menyimpan state di `.instagram-instagrapi.json` setiap run.
- **Siapa terdampak:** ops/owner.
- **Permission:** —
- **Tenant-aware:** No
- **Source:** `server/services/instagram-session.ts`, `ops/instagram/ig_feed.py`
