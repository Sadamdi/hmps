## Summary

Setelah rangkaian investigasi panjang (v4.19.1–v4.19.6) memverifikasi bahwa video Google Drive yang di-embed lewat iframe `/preview` tetap menampilkan player rusak (kotak hitam, garis progress tipis) **khusus di HP asli** — sementara PC dengan jendela diperkecil ke ukuran yang sama tetap normal, lintas browser dan mode incognito di HP tetap sama — kesimpulannya adalah Google sendiri menyajikan template player berbeda (dan rusak) berdasarkan User-Agent mobile asli, bukan sesuatu yang bisa diperbaiki dari sisi CSS/layout kita selagi masih memakai iframe milik Google.

Rilis ini mengganti pendekatan iframe dengan **proxy streaming server sendiri**: server mengambil byte video asli dari Google Drive API (menggunakan service account yang sudah ada) dan menyajikannya lewat elemen `<video>` native — persis seperti video upload biasa yang sudah terbukti jalan baik di semua device. Iframe `/preview` lama tetap dipertahankan sebagai fallback otomatis per-file kalau proxy gagal (mis. file ternyata tidak publik), dan owner mendapat toggle darurat di Dashboard Settings untuk mematikan seluruh mekanisme proxy ini kapan pun (mis. kalau ada kekhawatiran soal bandwidth server).

Risiko utama: bandwidth video kini lewat server kita sendiri (bukan CDN Google lagi) — dimitigasi dengan lazy-load on-scroll yang sudah ada sejak v4.19.5, header cache pada respons proxy, dan toggle kill-switch di atas.

## Highlights

- Video Google Drive kini diputar lewat `<video>` native (kontrol standar browser) alih-alih iframe Google yang rusak di mobile
- Fallback otomatis per-file ke iframe `/preview` lama kalau proxy gagal — tidak ada regresi untuk file yang tidak bisa diakses lewat API
- Toggle kill-switch owner baru di Dashboard → Settings → Appearance untuk mematikan proxy sepenuhnya kapan saja
- Tombol "Buka di Drive" (safety net dari v4.19.4) tetap ada di semua kondisi

## Features (detail)

### Feature A — Endpoint streaming proxy `/api/gdrive/stream/:fileId`
- **Masalah / tujuan:** Iframe `/preview` Google menampilkan player rusak di User-Agent mobile asli, di luar kendali kita.
- **Perilaku baru:** Server otentikasi ke Google Drive API pakai service account yang sudah ada (`server/googleDrive.ts`), lalu forward byte video asli (dengan dukungan `Range` header untuk seek/scrubbing) langsung ke klien via streaming pipe (bukan buffer penuh ke memory).
- **Siapa terdampak:** public (semua pengunjung yang menonton video Drive di halaman berita/library/dsb)
- **Permission:** tidak ada (endpoint publik, rate-limited via `gdriveProxyRateLimiter` yang sudah ada)
- **Tenant-aware:** Tidak relevan (endpoint media generik, tidak terikat tenant)
- **Source:** `server/routes.ts`, `server/googleDrive.ts` (`getDriveAccessToken`)

### Feature B — Client fallback logic di `MediaDisplay`
- **Masalah / tujuan:** Tidak semua file Drive pasti bisa diakses lewat API (mis. private/dihapus) — perlu fallback yang aman tanpa mematikan seluruh fitur.
- **Perilaku baru:** `MediaContent` dan `FullscreenModal` sama-sama coba `<video src="/api/gdrive/stream/:id">` dulu; kalau `onError` (proxy gagal), otomatis beralih ke iframe `/preview` lama untuk file tersebut (state `proxyStreamFailed`, di-reset tiap ganti file/slide). Lazy-load on-scroll (`driveIframeInView`, dari v4.19.5/4.19.6) tetap dipakai untuk kedua mode, supaya video yang belum di-scroll tidak langsung membebani bandwidth server.
- **Siapa terdampak:** public
- **Permission:** N/A
- **Tenant-aware:** N/A
- **Source:** `client/src/components/MediaDisplay.tsx`

### Feature C — Kill-switch owner di Dashboard Settings
- **Masalah / tujuan:** Owner perlu kontrol instan untuk mematikan proxy (mis. kalau bandwidth server jadi masalah) tanpa deploy ulang kode.
- **Perilaku baru:** Switch baru "Video Google Drive: Player Native" di tab Appearance, default aktif. Kalau dimatikan, klien langsung pakai iframe `/preview` lama tanpa mencoba proxy sama sekali.
- **Siapa terdampak:** owner/admin dengan permission `settings.animations`
- **Permission:** `settings.animations` (reuse permission yang sama dengan switch bubble-nav/auto-scroll yang sudah ada)
- **Tenant-aware:** No (setting global)
- **Source:** `client/src/pages/dashboard/settings.tsx`, `shared/schema.ts`, `db/mongodb.ts`

## User-facing impact

- Semua halaman yang memakai `MediaDisplay` dengan video Google Drive (berita, library, struktur organisasi, dsb.) — video sekarang tampil dengan player HTML5 native standar, bukan lagi player Google yang rusak di HP
- Loading state: sama seperti sebelumnya (spinner sebelum video masuk viewport), tidak ada perubahan UX loading
- Perlu smoke test manual: buka artikel berita dengan video Drive di HP asli, pastikan player native muncul dan bisa diputar; scroll ke beberapa video sekaligus untuk pastikan lazy-load tetap bekerja

## Security

- Endpoint proxy baru tidak menerima input bebas selain `fileId` (divalidasi regex `^[a-zA-Z0-9_-]+$` sebelum dipakai dalam URL), rate-limited via limiter gdrive yang sudah ada
- Tidak ada credential yang terekspos ke klien — access token Drive API hanya dipakai server-side untuk request ke Google, tidak pernah dikirim ke browser

## Notes / Known gaps

- Verifikasi live-site + HP asli belum dilakukan pada saat file ini ditulis — akan diverifikasi setelah deploy (curl endpoint proxy langsung + scroll-through di halaman nyata + minta user coba di HP asli, karena itu satu-satunya lingkungan yang tidak bisa direplikasi langsung dari sandbox pengembangan).
- Kalau proxy ternyata tetap gagal untuk sebagian besar file (mis. karena kuota API atau file yang belum benar-benar publik), fallback iframe lama tetap aktif secara otomatis — tidak ada video yang jadi sama sekali tidak bisa ditonton dibanding sebelum rilis ini.
- `docs/openapi.json`/`docs/api-docs.html` auto-generated dari `server/routes.ts` (lihat `scripts/generate-api-docs-html.mjs` + `server/swagger.ts`) menampilkan endpoint ini sebagai butuh auth (padlock bearerAuth/cookieAuth) — heuristik `isPublicEndpoint` di kedua generator itu hanya cocok untuk path yang **berakhir** dengan `/stream`, bukan `/stream/{fileId}`. Endpoint ini sebenarnya publik (tidak ada middleware auth di route-nya). Ini murni ketidakakuratan tampilan dokumentasi (pre-existing gap di heuristik, bukan regresi dari rilis ini — heuristik yang sama juga sudah salah untuk `/api/dashboard/system-health/stream` di arah sebaliknya), tidak diperbaiki di rilis ini karena di luar scope.
