## Summary

Tindak lanjut permintaan: bersihkan komentar payload, pastikan rate limit efektif, hilangkan password bawaan di semua alur pembuatan akun, matikan ClamAV, dan perbaiki backup yang terdampak batas 500 koleksi Atlas dengan retensi lebih pendek.

## Findings

- **Cluster backup:** 501 koleksi dari batas 500 (Atlas gratis, total lintas database). Isi: 7 snapshot utama (03–09), 11 snapshot komunitas, snapshot ONTAKI 2026_09 hanya 7 koleksi (terpotong saat penuh), tidak ada snapshot Oktober. Total data hanya ±41 MB; yang habis adalah jumlah koleksi, bukan ruang.
- **Rate limit:** konfigurasi limiter komentar sebenarnya ketat (10/menit per perangkat), tetapi dapat dimatikan penuh lewat toggle dashboard. Toggle diubah terakhir 15 Juli 2026 dan kini aktif; 382 komentar dalam 5 menit pada 3 Juli hanya mungkin bila limiter saat itu mati (kesimpulan dari pola, tidak terbukti langsung).
- **Password bawaan lain:** rute perbaikan owner komunitas memakai `'TempPass123!'` bila tidak diisi.
- **Backup tidak sengaja dari server uji:** startup server menjalankan backup ke `MONGODB_URI_BACKUP`. Server uji lokal harus dijalankan dengan variabel itu kosong (ditulis di SOP 12 dan docs backup).

## Changed

- `server/lib/backup-retention.ts` (baru, fungsi murni): `planPrune` dan `parseSnapshotName`. Simpan N terbaru per grup; snapshot terpotong (< 70% koleksi snapshot lebih lama) dibuang bila ada yang lengkap; komunitas tidak aktif dengan backup terakhir lebih tua dari retensi dibuang; snapshot lengkap terakhir situs utama/komunitas aktif tidak pernah dihapus.
- `server/services/db-backup.ts`: `pruneBackups` (mendukung `BACKUP_PRUNE_DRY_RUN=1`), `snapshotDatabase` (all-or-nothing), cek kapasitas `BACKUP_MAX_CLUSTER_COLLECTIONS` (480), `lastMonthlyBackupKey` hanya dicatat bila semua snapshot lengkap, backup manual ikut memangkas dan membersihkan snapshot parsial; daftar restore di UI mengikuti retensi baru. Env: `BACKUP_KEEP_MAIN` (3), `BACKUP_KEEP_TENANT` (2).
- `server/index.ts`: cron harian 03:30 untuk `runBackupIfNeeded` (selain tanggal 1 dan saat startup); log ClamAV.
- `server/middleware/public-rate-limit.ts`: opsi `alwaysOn`, kunci `maxPerSession` (hash cookie `authToken`/`buyerToken`); komentar IP 60/menit, perangkat 10/menit, sesi 6/menit (600/100/60 per hari); saran dan chat-upload `alwaysOn`.
- `server/routes.ts`: `POST /api/users` password opsional (acak 14 karakter, `generatedPassword` sekali di respons); rute perbaikan owner tanpa password bawaan (`tempPassword` hanya bila dibuat acak).
- `server/middleware/post-body-sanitize.ts`: tolak password umum pada `password`, `newPassword`, `ownerPassword` untuk rute selain login.
- `client/src/components/dashboard/user-management.tsx`: password boleh kosong saat membuat user; panel "Akun dibuat" menampilkan password acak sekali dengan tombol salin.
- `db/mongo-seed.ts`: password acak, dicetak sekali; tidak ada `allowWeak`.
- `server/services/file-scanner.ts`: ClamAV hanya bila `CLAMAV_ENABLED=1`.
- Docs: SOP 12 dan `docs/features/10-ops-security/03-backup-restore.md`.

## Verification

- `npm run check` lolos (setelah `npm ci` memulihkan pohon dependensi).
- Retensi pada daftar nyata cluster backup produksi (dibaca-saja): rencana pangkas situs utama 03–07, ONTAKI 06/07 dan 09 (terpotong), UINUX 05–08, gdgoc dan mocap (tidak aktif); tersisa 136 koleksi, cukup untuk backup Oktober; setelah Oktober 260 koleksi (batas 500). 13 kasus aman (snapshot terakhir tidak pernah dihapus, dsb.). `pruneBackups` diuji dengan klien palsu (dry-run tidak menghapus; mode nyata menghapus sesuai rencana).
- E2E server (DB uji, backup dikosongkan): password lemah ditolak (create/ubah → 400); Add User tanpa password → 201 + `generatedPassword` dan login berhasil; `admin123` pada akun lama → 403; toggle rate limit sengaja dimatikan, komentar sesi login tetap 429 setelah 6, tamu setelah 10 (13/13). Regresi upload 15/15, upload staf 8/8, sanitizer HTML 6/6.
- Dry-run skrip terhadap produksi (baca-saja): `cleanup-xss-comments` menemukan 384 komentar; `rotate-default-passwords` menemukan 9 akun (UINUX 4, ONTAKI 5), situs utama dan auroradev26 bersih.

## Notes / Known gaps

- Skrip pembersihan komentar dan rotasi password belum diterapkan pada produksi (aturan: tulis ke DB produksi dijalankan pemilik). Perintah: `node ops/cleanup-xss-comments.cjs --apply` dan `node ops/rotate-default-passwords.cjs --apply`.
- Pemangkasan backup berjalan otomatis di server produksi pada startup/cron berikutnya setelah deploy; hanya diuji dengan klien palsu dan fungsi murni, belum terhadap cluster Atlas asli.
- Sesi komunitas diterima endpoint situs utama (`authenticateOptional`) secara by design; komentar yang ditulis dengan sesi komunitas tersimpan di DB utama dengan ID pengguna komunitas.
- Retensi pendek berarti titik pulih maksimal 3 bulan (utama) dan 2 bulan (komunitas).
