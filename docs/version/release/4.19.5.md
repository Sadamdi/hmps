## Summary

Setelah `4.19.4` (tombol fallback "Buka di Drive") di-deploy, verifikasi ulang di production menunjukkan iframe video Drive **kembali** macet permanen jadi spinner — regresi yang sama seperti sebelum `4.19.3`, padahal fix dependency array `4.19.3` masih utuh di kode. Investigasi lebih dalam menemukan **root cause arsitektural yang sebenarnya**, yang kemungkinan besar jadi biang keladi seluruh rangkaian bug video sejak laporan pertama:

`MediaContent` dan `FullscreenModal` di `MediaDisplay.tsx` didefinisikan sebagai *nested function component* di dalam body fungsi `MediaDisplay` (`const MediaContent = () => {...}`), lalu dirender sebagai elemen JSX: `<MediaContent />`. Karena `MediaContent` didefinisikan ulang (function reference baru) **setiap kali `MediaDisplay` re-render**, React's reconciler melihat "tipe komponen berubah" di posisi itu pada setiap render — sehingga **selalu unmount subtree lama dan mount subtree baru**, walau isinya identik. Ini membuang dan membuat ulang seluruh DOM di dalamnya, termasuk div yang di-`ref` oleh `driveIframeContainerRef`.

Akibatnya: begitu `IntersectionObserver` berhasil attach ke sebuah elemen (dari fix `4.19.2`/`4.19.3`), render berikutnya (dipicu apa saja — mis. koneksi ulang `notif-stream`, state React Query lain, dsb.) langsung mengganti elemen itu dengan yang baru. Observer lama tetap "mengawasi" node lama yang sudah lepas dari DOM (tidak pernah `isIntersecting: true` lagi), sementara `driveIframeContainerRef.current` sudah menunjuk ke node baru yang **tidak pernah diobservasi** karena effect-nya tidak re-run (dependency array tidak berubah). Ini menjelaskan sifat *flaky* dari bug ini — kadang video sempat "berhasil" ke-load kalau kebetulan tidak ada re-render lain di antara mount dan scroll-into-view, kadang tidak.

Fix: ubah pemanggilan dari elemen JSX (`<MediaContent />`) menjadi pemanggilan fungsi langsung (`{MediaContent()}`) — dengan ini React tidak menganggapnya sebagai komponen terpisah sama sekali, hanya bagian JSX biasa dari render `MediaDisplay` sendiri, sehingga DOM & ref-nya stabil selama posisinya di tree tidak berubah (tidak ada unmount/remount tak perlu).

## Highlights

- Perbaiki root-cause arsitektural (bukan cuma gejala) di balik seluruh rangkaian bug player Drive video sejak awal laporan

## Features (detail)

### Fix — Hilangkan remount tak perlu pada MediaContent/FullscreenModal
- **Masalah / tujuan:** `<MediaContent />` dan `<FullscreenModal />` sebagai elemen JSX dari fungsi yang didefinisikan ulang tiap render memaksa React unmount+remount subtree-nya di setiap render `MediaDisplay`, merusak `ref` yang diandalkan `IntersectionObserver` untuk lazy-load iframe Drive.
- **Perilaku baru:** Dipanggil sebagai fungsi biasa — `{MediaContent()}` dan `{FullscreenModal()}` — bukan elemen JSX. React memperlakukannya sebagai bagian render `MediaDisplay` sendiri; DOM node & ref stabil selama tidak ada perubahan struktur JSX yang sesungguhnya.
- **Siapa terdampak:** publik — semua halaman yang memakai `MediaDisplay` (foto/video, Google Drive maupun lokal, single maupun folder/galeri)
- **Permission:** N/A
- **Tenant-aware:** N/A
- **Source:** `client/src/components/MediaDisplay.tsx`
