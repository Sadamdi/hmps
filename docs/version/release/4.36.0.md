## Summary

Sebelumnya toko belum punya pembayaran di web. Admin hanya mencatat metode bayar & tanggal bayar secara manual, dan pembeli membayar lewat chat WhatsApp.

Rilis ini menambahkan:
- **kanal bayar** yang diatur admin (QRIS, rekening, e-wallet);
- **bukti bayar** yang diupload pembeli di halaman invoice, lalu diverifikasi admin;
- **DP untuk produk pre-order** (default toko + override per produk);
- tab **Pre-order** untuk memantau siapa sudah DP / lunas / belum;
- editor pre-order di dashboard, yang sebelumnya hanya ada di server.

## Highlights

- Kanal bayar:
  - QRIS dengan nama merchant wajib;
  - daftar ±100 bank (BUMN, swasta, digital, syariah, BPD, asing) dan ±20 e-wallet/uang elektronik Indonesia, plus opsi "Lainnya";
  - on/off & urutan per kanal;
  - produk bisa memilih kanal.
- Keranjang dengan kanal berbeda dipecah otomatis menjadi beberapa pesanan (satu `checkoutGroupId`, ongkir sekali).
- DP:
  - persen + minimal nominal, atau nominal per pcs;
  - per produk: ikut default / persen / nominal / wajib penuh;
  - tenggat pelunasan (default estimasi siap / tutup PO);
  - ongkir & pajak ikut DP.
- Invoice:
  - cara bayar, "Saya sudah bayar" → upload bukti (ada tombol Kembali), konfirmasi WA;
  - riwayat pembayaran + alasan penolakan, sisa tagihan & tenggat;
  - batal sendiri bila belum bayar, selain itu permintaan batal ke admin.
- Admin:
  - verifikasi (bisa koreksi nominal) / tolak (alasan wajib);
  - catat bayar manual, tandai dana dikembalikan;
  - WA "Minta upload ulang" / "Ingatkan pelunasan";
  - ringkasan pengingat 09:00 WIB.
- Excel/Sheet: kolom R–X pembayaran, sheet Pre-order, KPI uang masuk & sisa tagihan.

## Features (detail)

### Change A — Aturan & data bersama
- **Source:** `shared/store-payment.ts`, `shared/store-payment-providers.ts`, `shared/store-order-status.ts` (status `preorder`)
- **Behavior:**
  - normalisasi & validasi kanal: QRIS wajib gambar + merchant; bank/e-wallet wajib nama, nomor, atas nama;
  - aturan DP efektif (`effectiveDpRule`), rencana bayar (`computeOrderPaymentPlan`), dan status bayar dari riwayat (`derivePaymentState`).

### Change B — Model
- **Source:** `db/mongodb.ts`, `db/tenant.ts`
- **Behavior:**
  - `StoreSettings.paymentChannels`, `StoreSettings.dp`;
  - `StoreProduct`: `paymentChannelMode`, `paymentChannelIds`, `dpMode`, `dpPercent`, `dpAmount`, `dpSettleBy`;
  - `StoreOrder`: `checkoutGroupId`, `paymentChannelsSnapshot`, `paymentPlan`, `dpAmount`, `amountPaid`, `balanceDue`, `settleBy`, `paymentStatus`, `payments[]`, `hasPreOrderItems`, `cancelRequest*`;
  - koleksi baru `StorePaymentProof` (main + tenant).

### Change C — API
- **Source:** `server/routes/store.ts`
- **Behavior:**
  - checkout dipecah per grup kanal (all-or-nothing: bila satu grup gagal, pesanan sebelumnya dihapus & stoknya dikembalikan);
  - `payment-preview`, upload/lihat bukti, batal/permintaan batal, verifikasi/tolak, bayar manual, daftar pre-order;
  - pengingat harian diperluas.

### Change D — UI pembeli

## User-facing impact

- **Pembeli:**
  - melihat info PO/DP di halaman produk;
  - memilih DP / penuh saat checkout;
  - bayar & upload bukti di invoice;
  - melihat status verifikasi dan sisa tagihan.
- **Admin:** mengatur kanal & DP, memverifikasi bukti, dan memantau pre-order dari satu tempat.
- Toko tanpa kanal bayar aktif tidak berubah (checkout → WhatsApp).

## Security

- Bukti bayar disimpan di database (tidak di `uploads/` yang publik & ikut git publik), dan hanya bisa dibuka pemilik pesanan / admin (`private, no-store`, `nosniff`).
- Upload bukti di-decode ulang ke WebP: EXIF/GPS dibuang, file non-gambar ditolak.
- Nominal dihitung server.
- Gambar QRIS harus hasil upload toko.
- Nomor rekening tidak ada di endpoint publik settings.

## Ops / Tooling

- Tidak ada perubahan server. Ukuran bukti sekitar 50–200 KB per gambar di MongoDB, jadi ratusan pesanan hanya menambah puluhan MB.
