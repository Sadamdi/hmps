## Summary

Setelah `4.20.0` di-deploy, verifikasi awal lewat scroll otomatis di halaman berita nyata menunjukkan 7/7 video Google Drive tetap macet sebagai spinner, dengan nol request yang pernah sampai ke endpoint proxy baru — mengindikasikan `IntersectionObserver` lazy-load tidak pernah trigger. Investigasi dengan debug `console.log` sementara (`0d50c0a`) mengonfirmasi observer **berhasil attach dengan benar** ke elemen yang tepat untuk semua 7 komponen (`hasEl: true`, `observer attached` ter-log), tapi callback intersection-nya tidak pernah terpanggil sepanjang sesi pengujian.

Penyebab sebenarnya ditemukan lewat `document.hidden`/`document.hasFocus()` yang mengembalikan `true`/`false` — tab pengujian tidak dalam status "displayed"/compositing dari sudut pandang browser (dikonfirmasi eksplisit oleh tool: "the Browser pane is not displayed, so the page is not compositing frames"). Chromium menahan (throttle) callback `IntersectionObserver` untuk tab yang tidak tampil/compositing, sehingga kegagalan ini murni keterbatasan lingkungan pengujian otomatis, bukan bug di kode `4.20.0`.

Untuk memverifikasi mekanisme inti secara independen dari observer, dibuat `<video>` element langsung menunjuk ke `/api/gdrive/stream/:fileId` di halaman nyata (bypass lazy-load gate) — berhasil `loadedmetadata` dengan `duration: 36.77s`, `videoWidth: 720`, `videoHeight: 1280` (dimensi video portrait asli, sesuai video rekaman HP). Ini membuktikan server proxy dan native video decode bekerja benar end-to-end; satu-satunya bagian yang tidak bisa diverifikasi visual dari sandbox ini adalah trigger scroll-into-view itu sendiri, karena keterbatasan tooling, bukan logika kode.

## Highlights

- Mekanisme inti `4.20.0` (server proxy streaming + native `<video>` decode) dikonfirmasi bekerja benar lewat pengujian langsung di production, independen dari lazy-load observer
- Root cause "video macet sebagai spinner" saat verifikasi teridentifikasi sebagai keterbatasan lingkungan pengujian (tab browser tidak compositing/visible), bukan bug kode
- Debug logging dihapus — tidak ada perubahan behavior

## Notes / Known gaps

- Verifikasi visual scroll-into-view di sandbox development tidak bisa dilakukan sepenuhnya karena Browser pane tidak dalam status compositing (`document.hidden: true`) selama sesi pengujian — ini keterbatasan tooling yang sudah beberapa kali ditemui di sesi ini (`resize_window` untuk viewport mobile juga punya keterbatasan serupa sebelumnya), bukan indikasi bug kode.
- Mekanisme inti (server proxy + native video decode) terbukti benar lewat `curl` dan `<video>` langsung — risiko yang tersisa hanya soal timing lazy-load-on-scroll di device nyata, yang perlu dikonfirmasi user secara langsung.
