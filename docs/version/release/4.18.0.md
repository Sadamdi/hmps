## Summary

Upgrade dashboard overview: System Health sekarang pakai SSE push real-time (2s, no-delay) menggantikan polling 10s. Ditambah widget **System Activity** (Network I/O RX/TX + Storage delta) dan **global range filter** 1d/3d/7d/30d yang menggantikan tombol range lokal di tiap widget. Permission matrix `overview.*` dirework agar admin & medinfo mendapat akses penuh, role lain disesuaikan sesuai kebutuhan operasional.

## Added

### SSE Push Channel
- Endpoint `/api/dashboard/system-health/stream` (GET, SSE)
  - Push tiap 2 detik dengan data `getSystemHealth()` + optional `getStorageBreakdown()` (jika punya perm `overview.storage_usage`)
  - Header: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no` (disable nginx buffering)
  - Heartbeat komentar `: keepalive` tiap 25s untuk mencegah proxy idle-timeout
  - Cleanup `setInterval` + listener `req.on('close')` saat client disconnect
  - Permission gate: `overview.system_health`

### `useOverviewStream` Hook
- `EventSource` subscribe ke `/api/dashboard/system-health/stream`
- Auto-reconnect dengan backoff eksponensial (1s, 2s, 4s, … max 15s)
- Setelah 3 kegagalan reconnect → fallback ke polling REST `/api/dashboard/system-health` tiap 10s
- Pause koneksi saat tab hidden (`visibilitychange`), reconnect otomatis saat visible
- Update React Query cache langsung via `queryClient.setQueryData(['/api/dashboard/system-health'], data)` — semua widget yang baca key ini langsung re-render tanpa poll
- Status: `{ connected, usingFallback, lastUpdate }` untuk indikator live

### System Activity Widget
- **Network I/O**: RX/TX rate (bytes/sec) dengan sparkline AreaChart, total bytes, daftar interfaces
  - Backend: `getNetworkStats()` di `system-health.ts` — baca `/proc/net/dev` (Linux) atau fallback `os.networkInterfaces()` (non-Linux)
  - Hitung rate dengan delta dari sample sebelumnya (in-memory, no `find`)
- **Storage Activity**: file count + size untuk `uploads/` & `attached_assets/`, plus delta sejak sample sebelumnya
  - Backend: `getStorageActivity()` — `fs.readdirSync` recursive dengan `statSync().size` (cepat untuk direktori kecil-menengah)
- Permission gate: `overview.network_activity` / `overview.storage_activity`

### Global Range Filter
- `OverviewRangeContext` + `OverviewRangeProvider` (default `7d`)
- Tombol global 1 Hari / 3 Hari / 7 Hari / 30 Hari di header "Analitik Overview" (di luar widget-widget)
- Widget yang sudah wired:
  - `visitor-graph` — query key + fetch pakai range dari context
  - `berita-leaderboard` — sama
  - `engagement-heatmap` — kirim `?days=N` ke backend
  - `content-performance` — kirim `?range=N` ke backend
  - `security-monitor` — kirim `?days=N` ke backend
  - `login-attempts` — kirim `?days=N` ke backend
- Backend endpoint sekarang accept `days` / `range` param dengan clamp (1-90 untuk heatmap/content, 1-30 untuk security/login)

### Permission Definitions
- `overview.network_activity` — "View Network Activity" — throughput jaringan real-time
- `overview.storage_activity` — "View Storage Activity" — delta file uploads/attached

## Ops Notes

- **SSE vs WebSocket**: SSE dipilih karena unidirectional (server→client), ringan, dan tidak butuh protocol upgrade. Cocok untuk metrics push. WebSocket tetap untuk notifikasi dua-arah.
- **Concurrent-safe**: tiap tab admin buka EventSource sendiri, server handle cleanup saat close. Tidak ada shared state lintas-tab di server.
- **Network/Storage helper**: in-memory snapshot dengan delta dari sample sebelumnya. Tidak ada `find`/`du` tiap tick — cepat bahkan untuk direktori ribuan file.
- **Fallback 10s**: tetap ada kalau SSE putus/proxy block. UX tidak blank. Indikator amber memberi sinyal ke admin bahwa mode polling aktif.
- **Permission rework**: tidak breaking secara runtime — role yang kehilangan perm tidak crash, hanya tidak melihat widget tersebut. Backfill reconcile memastikan konsistensi.
