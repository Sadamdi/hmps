## Summary

Setelah rilis 4.57.0, `clamd` (±960 MB, 48% RAM VPS 2 GB) masih berjalan dan baru hidup 1 menit setelah deploy 4.60.0. Penyebab: `disable_clamav_if_requested` hanya jalan bila `is-enabled` benar; bila tidak (mis. aktivasi lewat socket), `stop_heavy_services` menghentikan clamd saat build lalu `start_heavy_services` menyalakannya lagi di akhir deploy.

## Changed

- `ops/deploy-server.sh`: `disable_clamav_if_requested` kini tanpa syarat `is-enabled`: `systemctl mask --now` untuk `clamav-daemon.socket`, `clamav-daemon.service`, `clamav-freshclam.service`, hentikan proses `clamd` bila masih ada, dan hapus `clamav-daemon` dari `STOP_SERVICES` agar tidak dinyalakan lagi. Dipanggil juga pada jalur deploy tanpa build.

## Verification

- `bash -n` lolos. Belum dijalankan di server (tidak ada akses dari sesi ini).

## Notes / Known gaps

- Skrip baru baru berlaku pada deploy BERIKUTNYA setelah commit ini terambil (deploy yang membawa commit ini masih memakai skrip lama). Percepat dengan menjalankan sekali di server: `systemctl mask --now clamav-daemon.socket clamav-daemon.service clamav-freshclam.service`.
- Untuk menyalakan ClamAV lagi: `systemctl unmask ...` dan set `HMPS_DISABLE_CLAMAV=0`.
