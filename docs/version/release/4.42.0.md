## Summary

Pembeli bisa punya akun (opsional) untuk menyimpan semua pesanan dan membukanya dari perangkat mana pun. Akun pembeli terpisah total dari akun pengurus, jadi pembeli tidak bisa masuk dashboard admin.

## Added

- **Model:** `Customer` + `CustomerSession` (DB utama, satu akun untuk semua toko); `StoreOrder.buyerId`, `StoreChat.buyerId`.
- **Auth pembeli** (`server/services/buyer-auth.ts`):
  - cookie `buyerToken`, JWT `aud: buyer` dengan kunci turunan, `sid` + `tokenVersion`;
  - `authenticateBuyer`, `getBuyer`.
- **API `/api/buyer/*`:**
  - daftar + verifikasi OTP email, masuk email/password, masuk Google (Firebase yang sudah ada), keluar;
  - profil, lupa/atur password via OTP (semua sesi lama dicabut), ganti email via OTP;
  - pesanan di semua toko, klaim lewat link invoice, sesi aktif.
- **Klaim otomatis pesanan lama:** dari perangkat yang sama (cookie toko) dan dari email terverifikasi, di toko utama + semua toko komunitas. Tidak pernah berdasarkan no HP.
- **Checkout:** pembeli yang masuk → `buyerId` tercatat. Pesanan akun bisa dibuka dari perangkat lain tanpa link `inv`.
- **UI:**
  - `{toko}/masuk` dan `{toko}/daftar`;
  - `{toko}/akun` (Ringkasan, Pesanan saya + klaim link, Profil & keamanan);
  - tombol Masuk/nama di header toko;
  - kartu ajakan masuk + isi otomatis di checkout dan beli-langsung.
- **Docs:** feature doc 12, `endpoints.md`, OpenAPI (`ops/openapi-add-buyer.cjs`, skema `buyerCookieAuth`).
- **Email OTP:** label pembeli + mode uji `STORE_EMAIL_OUTBOX` (hanya pengujian).

## Security

- Token pembeli → endpoint staf/dashboard = 401. Token staf di cookie pembeli = 401. Login staf ≠ login pembeli.
- Rate limit `buyer-auth` + kuota OTP bawaan. Lupa password tidak membocorkan email terdaftar.
- Hash password tidak pernah dikirim.
