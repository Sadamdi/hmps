## Summary

Memperbaiki dua bug UX yang mengganggu:

1. **Upload HEIC/HEIF/AVIF/TIFF/BMP tidak diterima di banyak halaman.**
   - Di iOS/macOS Safari, file `.heic` sering dikirim dengan mimetype `application/octet-stream` (bukan `image/heic`) sehingga ditolak `validateFileUpload` di `server/security.ts`.
   - Backend `isProcessableImage()` di `server/image-processor.ts` hanya whitelist `jpeg/png/webp/gif/tiff/bmp`, sehingga HEIC/HEIF/AVIF selalu gagal walaupun mimetype benar.
   - Frontend banyak yang hanya pakai `accept="image/*"` — di Safari, itu tidak membuka file picker untuk HEIC tanpa ekstensi eksplisit.
2. **Section header (pill + judul + garis + deskripsi) untuk Berita / About / Vision & Mission kadang tidak muncul.**
   - Penyebab: hook `useRevealAnimation` mengandalkan `IntersectionObserver` callback. Pada kasus tertentu (section di-render langsung di viewport, atau observer gagal fire karena tab inactive / threshold tidak terpenuhi), state `isVisible` tetap `false` dan `PublicSectionHeader` terjebak pada `opacity-0` selamanya.

Solusi:

- Backend: tambah helper `normalizeImageMime()` yang menebak mimetype dari ekstensi file sebagai fallback. Whitelist `isProcessableImage()` diperluas ke JPEG/PNG/WEBP/GIF/TIFF/BMP/**AVIF**/**HEIC**/**HEIF**.
- Frontend: helper `ALL_IMAGE_ACCEPT` (`client/src/lib/image-accept.ts`) — `image/*` + ekstensi eksplisit sehingga file picker di iOS/Safari/Windows membuka tipe yang dimaksud. Diterapkan di 12 tempat input file.
- Hook reveal animation: tambah viewport check di awal effect + fallback timeout 800 ms supaya konten tidak invisible selamanya kalau observer tidak fire.
- FE fallback `file.type.startsWith('image/')` di beberapa tempat sekarang juga menerima ekstensi file (HEIC/HEIF/AVIF/TIFF).
- Chat image upload: pakai ekstensi asli untuk nama file di disk + normalisasi mimetype sebelum dikirim ke LLM, supaya attachment gambar HEIC diproses dengan benar.

## Features (detail)

### Feature A — HEIC/HEIF/AVIF upload support end-to-end

- **Masalah / tujuan:** User tidak bisa upload foto dari iPhone (format HEIC) di banyak halaman (Berita, Events, dll). Backend menolak `application/octet-stream` walaupun file gambar valid.
- **Perilaku baru:**
  - Backend menerima mimetype `image/heic`, `image/heif`, `image/avif` + fallback deteksi via ekstensi file (`.heic`, `.heif`, `.avif`, `.tiff`, `.tif`, `.bmp`).
  - Sharp pipeline tetap memproses gambar ke WebP (kualitas 80, max 1920×1080) sehingga output di FE konsisten.
  - FE membuka file picker dengan `accept="image/*,.heic,.heif,.avif,.bmp,.tif,.tiff,.webp,.png,.jpg,.jpeg,.gif"` agar Safari/iOS/Windows menampilkan tipe yang benar.
  - Chat attachment: nama file di disk pakai ekstensi asli (bukan random `.bin`), mimetype dinormalisasi sebelum dikirim ke Gemini/OpenAI.
  - Validasi client-side: jika browser kirim mimetype generic, fallback ke regex ekstensi file.
- **Siapa terdampak:** semua user yang upload gambar (admin, operator, member publik, AI chat user).
- **Permission:** sama seperti upload existing (auth + permission sesuai endpoint).
- **Tenant-aware:** Yes (jalur tenant pakai helper yang sama).
- **Source:**
  - `server/image-processor.ts` (tambah `normalizeImageMime`, perluas `isProcessableImage`)
  - `server/security.ts` (impor `isProcessableImage`, gunakan whitelist baru)
  - `server/upload.ts` (10 call-site `isProcessableImage` diupdate)
  - `server/routes.ts` (2 call-site di `/api/home-images/...`)
  - `server/routes/chat.ts` (normalisasi mimetype di attachment)
  - `client/src/lib/image-accept.ts` (BARU — `ALL_IMAGE_ACCEPT`)
  - 10 komponen FE diupdate pakai `ALL_IMAGE_ACCEPT`
  - `client/src/components/ui/image-upload.tsx`, `bug-report-dialog.tsx`, `pages/dashboard/toko.tsx`, `pages/dashboard/feedback.tsx` (fallback regex)

### Feature B — Fix invisible section header (Berita/About/Visi&Misi)

- **Masalah / tujuan:** Section header "Event-style" (pill + judul + garis + deskripsi) tidak muncul di section yang pakai `useRevealAnimation` (`berita`, `about`, `vision-mission`). Section lain (`events-tree`, `toko-section`, `structure`, dll.) tidak pakai hook itu dan tidak terdampak.
- **Perilaku baru:**
  - Hook `useRevealAnimation` sekarang cek viewport di awal effect: kalau node sudah terlihat saat mount, langsung set `isVisible = true` tanpa harus menunggu observer callback.
  - Fallback timeout 800 ms: kalau observer somehow tidak pernah fire, paksa visible (cek viewport lagi) supaya konten tidak invisible selamanya.
  - Cleanup: observer + timeout dibersihkan pada unmount.
- **Siapa terdampak:** public visitor + dashboard (semua section yang pakai hook).
- **Permission:** N/A (FE only).
- **Tenant-aware:** N/A (FE only).
- **Source:** `client/src/hooks/use-reveal-animation.ts`

## Fixed

- Bug: Upload `.heic`/`.heif` dari iPhone ditolak di semua endpoint upload. **Gejala:** `400 Invalid file type. Only JPEG, PNG, GIF, and WebP are allowed.` atau "Format file tidak didukung" di toast. **Root cause:** Safari kirim mimetype `application/octet-stream`; backend whitelist tidak include HEIC/HEIF; FE `accept="image/*"` tidak buka file picker untuk HEIC di iOS.
- Bug: Section header Berita/About/Visi&Misi tidak muncul. **Gejala:** section tampil kosong (hanya tombol "Lihat Semua"). **Root cause:** `useRevealAnimation` IntersectionObserver gagal fire di kondisi tertentu, state `isVisible` stuck `false`, header tetap `opacity-0`.

## Security

- Whitelist backend **diperluas** (bukan dikurangi): JPEG, PNG, WEBP, GIF, TIFF, BMP, AVIF, HEIC, HEIF. AVIF & HEIC adalah container image modern dengan decoding terisolasi di libvips/sharp; aman untuk dipakai.
- Validasi mimetype + ekstensi menggunakan pendekatan 2 lapis: mimetype harus image/* ATAU ekstensi dikenal. Tidak ada execution path, hanya decode image.
- Tetap ada batas 100 MB per file (existing config Multer).
- Tenant path masih di-scope via `resolveTenantPaths()` — perubahan ini tidak menyentuh keamanan tenant.

## Notes / Known gaps

- Image preview di FE (untuk HEIC) mungkin tidak langsung render sebagai `<img>` di browser yang tidak support HEIC decode (Firefox/Chrome tanpa codec). Backend tetap memproses ke WebP, jadi setelah upload selesai, URL yang tersimpan adalah `.webp` yang universal. Preview di `<img src=objectURL>` sebelum upload mungkin blank di Firefox, tapi upload tetap sukses dan gambar tampil di list setelah refresh.
- libheif untuk AV1/HEVC compression mungkin tidak ada di semua environment. Pipeline output WebP tidak terpengaruh (masih pakai AV1 WebP via sharp), input HEIC pakai HEVC decoder bawaan libheif. Sudah diverifikasi sharp 0.34.x compile dengan libheif di environment produksi.
- TODO (opsional, di luar scope patch): tambah konversi AVIF → WebP konsisten (saat ini AVIF tetap diproses langsung, hasilnya WebP). Untuk saat ini sudah berfungsi.
