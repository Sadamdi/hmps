## Summary

Di editor berita (`/dashboard/berita`), upload thumbnail dilakukan bersamaan dengan klik **Simpan Berita**. Untuk file JPEG/PNG/WebP kecil, ini cepat. Tapi untuk **HEIC/HEIF dari iPhone** atau **AVIF modern**, server butuh decode via `heic-convert` (pure-JS) atau pipeline `sharp` — proses ini 5–10 detik per file. Sebelumnya user klik Simpan dan **tidak ada feedback visual sama sekali** karena endpoint `POST /api/berita` mengembalikan respons setelah thumbnail selesai diproses — terasa "lama" atau bahkan "hang" padahal server sedang kerja.

Patch ini memecah upload thumbnail dari save:

1. **Pilih file** → frontend langsung upload ke endpoint baru `POST /api/upload/berita-thumbnail` (background, progresif).
2. **Server proses gambar** (HEIC/AVIF/JPG/PNG → WebP via pipeline `processImage`).
3. **Preview tampil** dari URL final server (bukan blob URL lokal).
4. **Simpan Berita** → frontend tinggal kirim URL final via field `imageUrl` — server tidak upload file lagi (idempotent).

User dapat feedback loading + progress bar di preview thumbnail selama proses, sehingga UI tidak terasa hang. HEIC iPhone sekarang bekerja seperti biasa: pilih → loading 5–10 detik → preview WebP → simpan.

## Highlights

- **Progressive upload**: pilih file thumbnail → loading + progress bar → preview WebP final dari server. Tidak perlu tunggu tombol Simpan.
- **HEIC/AVIF support end-to-end di `/dashboard/berita`**: file dari iPhone (HEIC) atau browser modern (AVIF) sekarang benar-benar bisa di-upload via UI ini, bukan hanya via endpoint generic `/api/upload`.
- **Idempotent save**: server bisa terima URL final via `imageUrl` field — tidak upload ulang file yang sudah diproses.
- **Migration**: file `_draft/{draftId}/thumbnail-...webp` otomatis dipindah ke `{beritaId}/thumbnail-...webp` saat berita disimpan — tidak ada file yang nyangkut di `_draft`.
- **Loading state**: tombol Simpan, gambar dari preview, dan tombol Pilih gambar disabled saat upload berjalan.
- **Error handling**: pesan error dari server tampil di bawah preview + toast.
- **No-breaking**: kontrak API existing (`POST /api/berita` dengan field `image`) tetap bekerja untuk client lama (mis. mobile app yang belum update).

## Features (detail)

### Feature / Change A — Endpoint `POST /api/upload/berita-thumbnail`

- **Masalah / tujuan:** tidak ada endpoint khusus untuk upload thumbnail berita tanpa `beritaId`. Endpoint existing `/api/upload/content-image` wajib `beritaId` (untuk image di dalam konten), dan `/api/upload/berita-attachment` wajib `beritaId` (untuk file attachment). Untuk draft baru, FE tidak punya `beritaId` sampai save — chicken-and-egg problem.
- **Perilaku baru:**
  - `POST /api/upload/berita-thumbnail` (auth + multer single 'image'):
    - Body: `image` (file), `beritaId` (optional), `draftId` (optional).
    - Tanpa `beritaId` valid (atau `beritaId.startsWith('temp-')`): simpan ke `uploads/berita/_draft/{draftId}/thumbnail-{ts}.webp`. Default `draftId = session-{Date.now()}` kalau tidak dikirim.
    - Dengan `beritaId` valid (existing berita): simpan ke `uploads/berita/{beritaId}/thumbnail-{ts}.webp`.
    - Pipeline `processImage()` (sharp + `heic-convert` fallback) handle HEIC/HEIF/AVIF/TIFF/BMP/JPEG/PNG/WebP/GIF → output selalu WebP.
    - Response: `{ url, subFolder, draftId }`.
  - 400 kalau tidak ada file. 500 dengan pesan error readable kalau pipeline gagal (mis. format tidak dikenal).
- **Siapa terdampak:** editor berita (admin/owner), editor tenant (kalau tenant punya fitur berita).
- **Permission:** auth wajib. Tidak ada per-file permission check khusus — disyaratkan user yang login sudah punya akses ke dashboard.
- **Tenant-aware:** Yes — lewat `tenantCtxFromReq(req)`, simpan ke tenant folder kalau applicable.
- **Source:** `server/routes.ts` line ~2671.

### Feature / Change B — `POST /api/berita` & `PUT /api/berita/:id` terima field `imageUrl`

- **Masalah / tujuan:** setelah FE upload thumbnail progresif, FE punya URL final WebP. Endpoint `POST /api/berita` existing cuma proses file multipart di field `image` — kalau FE kirim `imageUrl` string, server abaikan dan pakai default image. Endpoint `PUT /api/berita/:id` sama — kalau tidak ada `image` file, image existing dipakai.
- **Perilaku baru:**
  - `POST /api/berita`:
    - Kalau body `imageUrl` dikirim dan starts with `/uploads/`: pakai sebagai `imageUrl` (skip upload file lokal).
    - Kalau `image` file juga dikirim: proses seperti biasa (backward compat).
  - `PUT /api/berita/:id`:
    - Kalau body `imageUrl` dikirim: pakai sebagai thumbnail baru, hapus thumbnail lama (kalau ada dan berbeda), skip upload file.
    - Kalau `image` file dikirim: proses seperti biasa.
- **Migration `_draft` → `{beritaId}`**: step "Migrate temp draft assets" sudah ada untuk `temp-{id}` (legacy) dan sekarang juga handle `_draft/{draftId}/`. File WebP thumbnail dipindah dari `_draft/draftId/` ke `beritaId/`, URL di field `image` di-rewrite agar konsisten.
- **Siapa terdampak:** editor berita (semua role yang bisa edit).
- **Source:** `server/routes.ts` POST/PUT handlers.

### Feature / Change C — Berita editor progressive upload UI

- **Masalah / tujuan:** user tidak tahu upload sedang proses saat klik Simpan, terutama untuk HEIC/AVIF yang butuh 5–10 detik decode. UX terasa "hang".
- **Perilaku baru:**
  - `handleFileChange`: pilih file → set `imagePreview=blobURL` (preview lokal synchronous), set `selectedFile=file`, langsung panggil `uploadThumbnailMutation` (background).
  - `uploadThumbnailMutation`:
    - `mutationFn`: form data → `POST /api/upload/berita-thumbnail` (dengan `draftId` dari `_id` existing berita atau `draft-{Date.now()}`).
    - Tick progress setiap 220 ms (15% → max 92%, untuk visual feedback).
    - `onSuccess`: `setImageUrl(serverUrl)`, ganti `imagePreview` dari blob ke URL server (revoke blob lama), `setSelectedFile(null)`, toast "Thumbnail siap".
    - `onError`: `setThumbnailUploadError`, toast "Upload thumbnail gagal" dengan pesan dari server.
  - UI:
    - Preview thumbnail 32×32: spinner overlay + progress bar saat upload. Disabled click saat uploading.
    - Tombol "Pilih gambar" / "Ganti gambar" disabled saat uploading.
    - Tombol "Hapus" muncul kalau ada preview dan tidak uploading — hapus preview + reset state.
    - Help text: daftar 9+1 format gambar (JPEG, PNG, WebP, GIF, AVIF, HEIC, HEIF, TIFF, BMP) + kalimat "Server otomatis konversi ke WebP".
    - Status indicator: "✓ Thumbnail sudah tersimpan di server (WebP)" kalau upload sukses, error message merah kalau gagal.
    - Tombol "Simpan Berita": kalau `isThumbnailUploading` true → block save dengan toast "Tunggu upload thumbnail selesai".
  - `handleSave`: kirim `imageUrl` (URL final server) instead of file kalau sudah ke-upload. Tetap support `image` file untuk backward compat.
- **Siapa terdampak:** admin/owner yang edit berita.
- **Source:** `client/src/components/dashboard/berita-editor.tsx`.

## Fixed

- **Bug UX:** Upload thumbnail HEIC/AVIF terasa "lama" atau "hang" tanpa feedback karena server-side decode butuh 5–10 detik. **Gejala:** klik Simpan → loading 5–10 detik tanpa UI feedback → user bingung. **Root cause:** thumbnail di-upload bareng save di `POST /api/berita`, server proses di backend tanpa ada indikasi progress ke FE. **Fix:** progressive upload via endpoint baru `POST /api/upload/berita-thumbnail` yang langsung fire saat user pilih file, dengan loading spinner + progress bar + status indicator di UI. Server tetap decode HEIC/AVIF di endpoint yang sama (pakai pipeline `processImage` existing).

- Tidak ada upload yang lewat tanpa auth — sama seperti endpoint lain.
