## Summary

Audit lanjutan laporan "bisa masuk sebagai admin" menemukan proses produksi berjalan tanpa `JWT_SECRET`, sehingga token login ditandatangani dengan kunci bawaan yang tercantum di repo publik. Siapa pun yang membaca kode secara teori dapat membuat token untuk user mana pun tanpa password, dan middleware menerima token tanpa `sid`. Rilis ini mewajibkan `JWT_SECRET` ≥32 karakter di produksi (app menolak start), mengunci algoritma ke HS256, dan menolak token tanpa `sid`. `JWT_SECRET` acak telah dipasang di `.env` server sehingga semua token lama tidak berlaku. Selain itu bridge Instagram memakai cookie browser yang lebih baru dari sesi tersimpan.

## Highlights

- Produksi gagal start bila `JWT_SECRET` kosong/lemah.
- `jwt.verify` hanya HS256; token tanpa `sid` → 401.
- `JWT_SECRET` baru di server → semua sesi lama logout.
- `ig_feed.py`: cookie ekspor baru otomatis dipakai.

## Features (detail)

### Change A — Kunci JWT
- **Masalah / tujuan:** pemalsuan token dengan kunci bawaan publik.
- **Perilaku baru:** guard start produksi; `algorithms: ['HS256']`; `authenticate` & optional auth menolak token tanpa `sid`.
- **Siapa terdampak:** semua pengguna (login ulang sekali).
- **Permission:** tidak berubah.
- **Tenant-aware:** Yes
- **Source:** `server/auth.ts`

### Change B — Cookie Instagram baru
- **Perilaku baru:** bila `.instagram-session.json` lebih baru dari `.instagram-instagrapi.json`, login lewat sessionid cookie itu dulu.
- **Source:** `ops/instagram/ig_feed.py`
