## Summary

Satu profil browser bisa kena Error 503 “Max Connections: 48 concurrent” sementara profil/device lain aman. Root cause: `ddos-protection` meng-increment concurrent slot lalu early-return sebelum `res.on('finish')` (leak), plus sweep `now % 300000 === 0` yang hampir tidak pernah jalan. Slot release sekarang di `finish`+`close` dengan single-release guard; sweep tiap 5 menit via timestamp; default device limit 64; path ringan SPA (vapid-key/health) skip concurrent slot saja. API protection Origin/auth tidak diubah.

## Highlights

- Concurrent connection accounting tidak leak lagi
- Sweep stuck counters tiap 5 menit benar-benar jalan
- Default `DDOS_MAX_CONCURRENT_PER_DEVICE` 48 → 64
- Observability: `getDdosStats` expose max concurrent per device/IP

## Features (detail)

### Fix concurrent slot leak — ddos-protection
- **Masalah / tujuan:** Counter stuck → false-positive 503 per device fingerprint
- **Perilaku baru:** `acquireConcurrentSlot` + release sekali di finish/close; early return aman
- **Siapa terdampak:** public browsing multi-tab
- **Permission:** N/A (middleware global)
- **Tenant-aware:** No
- **Source:** `server/middleware/ddos-protection.ts`

## User-facing impact

- Halaman error `/error` 503 concurrent seharusnya jarang muncul untuk browsing normal
- Smoke: buka banyak tab himatif + DevTools; profil lain tetap OK; curl tanpa Origin ke API sensitif tetap ditolak

## Added

- Env-documented defaults & skip list for vapid-key/health concurrent slot
- Stats fields: `maxConcurrentPerDevice`, `maxConcurrentPerIp`, `concurrentLimits`

## Changed

- Default device concurrent limit 48 → 64
- Connection map sweep uses `lastConnectionSweepAt` instead of modulo

## Fixed

- Leak when login/upload/suspicious early-return after increment without finish listener
- Broken 5-minute clear (`Date.now() % 300000 === 0`)

## Security

- Hardening of anti-abuse accounting; API Origin/Referer protection unchanged — 503 concurrent is not API openness

## Ops / Tooling

- PM2 restart still clears in-memory maps; after deploy, stuck profiles recover within sweep interval without restart
